## 1. 目的・背景

Phase 6-Aで「プレイ記録」のデータモデルとRepositoryは整った。本フェーズではそれをユーザーが実際に使えるようにする。ゲーム詳細画面から記録を追加でき、過去の記録を一覧で振り返り、不要な記録は削除できる、という最小限のCRUD（Update除く）をUIとして提供する。

### 1.1 設計の前提

- **記録の追加先は常に「ゲーム詳細画面」**。Phase 6-Aの制約どおり、対象は基本ゲーム（`gameKind != 'expansion'`）のみ。拡張の詳細画面には記録フォームを置かず、「基本ゲームの詳細画面から記録してください」という案内のみを表示する。拡張側にはPhase 5で実装済みの「拡張情報」セクションに親ゲームへのリンクが既にあるため、本フェーズではそれ以上の重複した親解決は行わない。
- **編集（修正）機能はv1では実装しない**。追加と削除のみ。記録内容を直したい場合は削除して再登録する運用とする。これは「小さく確実に」の方針に基づくスコープ限定であり、Phase 6-B′等で将来追加可能。
- **評価系3項目（評価/また遊びたい度/重さの体感）は、ドロップダウンによる選択式（未評価=nullを含む）とする**。Phase 6-Aで定義したスケール（評価1-10、また遊びたい度1-5、重さの体感1.0-5.0・0.5刻み）をそのまま選択肢にする。スライダー等は使わず、シンプルなフォーム部品に統一する。
- **使用拡張のチェックボックスは、その基本ゲームに登録済みの拡張（`findExpansions(gameKey)`）のみを選択肢にする**。これによりPhase 6-Aのバリデーション（拡張は記録対象ゲームの拡張であること）に必ず合致し、`PlaySessionValidationException`が発生しない。
- **新規の一覧専用ページは作らない**。プレイ履歴はゲーム詳細画面内の「プレイ記録」セクションに表示する（ゲーム横断の履歴一覧はPhase 6-C/6-D で必要になれば検討）。

## 2. スコープ

### 2.1 含むもの（In Scope）

- FR-6B-01 ゲーム詳細画面に「プレイ記録」セクションを追加
  - 基本ゲーム: プレイ回数表示、履歴一覧、「プレイ記録を追加」ボタン
  - 拡張: 「プレイ記録は基本ゲームから記録してください」という案内のみ
- FR-6B-02 プレイ記録入力フォーム（新規ページ）。日付・プレイ人数・実プレイ時間・使用した拡張（チェックボックス、複数選択）・評価・また遊びたい度・重さの体感・感想メモ・勝者メモを入力し、`PlaySessionRepository.recordSession`を呼び出す
- FR-6B-03 履歴一覧の各記録を削除できる（確認ダイアログ付き）
- FR-6B-04 `PlaySessionValidationException`発生時のエラー表示（i18n化）
- FR-6B-05 新規UI文言の`assets/i18n/{ja,en}.json`への追加

### 2.2 含まないもの（Out of Scope）

- 記録の編集（修正）機能
- ゲーム横断のプレイ履歴一覧ページ
- 写真添付
- 人数・時間・メカニクス・デザイナー等での絞り込み・「探す」画面 → Phase 6-C
- デザイナー別/メカニクス別集計、評価傾向分析等 → Phase 6-D
- プレイヤー別スコア・勝敗の構造化UI

## 4. UI仕様

### 4.1 詳細画面「プレイ記録」セクション

- 配置: 「拡張情報」セクションの直後、「分析」セクションの前
- 基本ゲーム（`gameKind != 'expansion'`）の場合:
  - `playSessionListProvider(gameKey)`から記録一覧を取得
  - 記録が0件: 「まだプレイ記録はありません」を表示
  - 1件以上: 「{件数}回プレイ済み」を表示し、各記録を以下の内容でタイル表示
    - 日付
    - プレイ人数 / 実プレイ時間（いずれかが未入力の場合は該当部分を省略）
    - 評価 / また遊びたい度 / 重さの体感（入力されている項目のみ表示）
    - 使用した拡張（あれば名称をまとめて表示。複数記録にまたがる拡張名は一括解決してから表示する）
    - 感想メモ（あれば、複数行可・適度に省略）
    - 勝者メモ（あれば）
    - 削除アイコン（確認ダイアログ→削除）
  - セクション末尾に「プレイ記録を追加」ボタン（`PlaySessionFormPage`へ遷移）
- 拡張（`gameKind == 'expansion'`）の場合:
  - 「プレイ記録は基本ゲームから記録してください」という案内文のみを表示する（親ゲームへのリンクは既存の「拡張情報」セクションに既にあるため、ここでは再掲しない）

### 4.2 プレイ記録入力フォーム（新規ページ・`PlaySessionFormPage`）

| 項目 | 入力UI | 既定値 | 必須/任意 |
|---|---|---|---|
| 日付 | `showDatePicker` | 本日 | 必須 |
| プレイ人数 | 数値入力（整数） | 空 | 任意 |
| 実プレイ時間（分） | 数値入力（整数） | 空 | 任意 |
| 使用した拡張 | チェックボックス一覧（`findExpansions(gameKey)`の結果） | すべて未選択 | 任意（登録済み拡張が0件の場合は「登録済みの拡張はありません」と表示） |
| 評価 | ドロップダウン（1〜10 ＋「未評価」） | 未評価 | 任意 |
| また遊びたい度 | ドロップダウン（1〜5 ＋「未評価」） | 未評価 | 任意 |
| 重さの体感 | ドロップダウン（1.0〜5.0・0.5刻み ＋「未評価」） | 未評価 | 任意 |
| 感想メモ | 複数行テキスト | 空 | 任意 |
| 勝者・スコアなど | テキスト | 空 | 任意 |

- 保存ボタン押下で`PlaySessionInput`を構築し`recordSession`を呼ぶ
- 成功時: 「プレイ記録を保存しました」を表示し、詳細画面に戻り一覧を更新する
- `PlaySessionValidationException`発生時: 画面に留まり、エラー内容に応じたメッセージを表示する（日付不正・評価系の範囲外など。Phase 6-Aのバリデーションにより、人数・時間・拡張の組み合わせは画面の入力UIの作りで通常は発生しない想定だが、念のため汎用エラー文言を用意する）

### 4.3 履歴一覧の拡張名表示

- 一覧に表示する全記録の`expansionGameKeys`から重複を除いた一覧を作り、`AppDatabase.findGame`で一括解決してgameKey→表示名のMapを構築する。各記録のタイルはこのMapを参照して拡張名を表示する（記録ごとに個別の非同期解決は行わない）

### 4.4 削除

- 各記録の削除アイコン押下時、既存の削除確認ダイアログ（`detail.deleteConfirmTitle`/`detail.deleteConfirmBody`と同様の構成）を表示し、確認後に`PlaySessionRepository.deleteSession(id)`を呼び、一覧を更新する

## 6. 受け入れ基準（概要）

- 基本ゲームの詳細画面に「プレイ記録」セクションが表示され、記録が0件のときは「まだプレイ記録はありません」、1件以上のときは「{件数}回プレイ済み」と各記録の一覧が表示される
- 拡張の詳細画面には「プレイ記録は基本ゲームから記録してください」のみが表示され、入力フォーム・履歴一覧は表示されない
- 「プレイ記録を追加」から`PlaySessionFormPage`に遷移し、日付・人数・実プレイ時間・使用拡張（登録済み拡張のみが選択肢）・評価・また遊びたい度・重さの体感・感想メモ・勝者メモを入力して保存できる
- 保存後、詳細画面の履歴一覧が更新され、新しい記録が表示される
- 評価/また遊びたい度/重さの体感は「未評価」を選択でき、その場合`null`として保存される
- 履歴一覧の各記録に削除アイコンがあり、確認ダイアログを経て削除できる。削除後一覧が更新される
- 複数の記録に同じ拡張が紐づく場合も、拡張名の解決が記録数分の重複呼び出しにならない
- すべての新規UI文言がja/en両方のi18nファイルに存在する
- `flutter analyze` 警告ゼロ、`flutter test` 全件パス

詳細なタスク分割・定数・実装制約は `docs/DEVELOPMENT_BRIEF_Phase6-B.md` を参照。
