## 1. 目的・背景

Phase 0 では最大の技術リスク（バーコード解決・画像認識）を切り離し、コア価値（ローカルDB＋BGG検索登録＋analyzer互換YAML）を完成させた。Phase 1-A はそのうち **JAN/EAN-13 バーコードのカメラ読み取りによる登録動線** だけを追加する。棚全体検出や画像AIは含めない（リスク集中を避けるため）。

### 1.1 最重要の制約（設計の前提）

**BoardGameGeek の API には JAN/バーコード検索が存在しない。** したがって JAN コード単体から BGG ゲームを自動解決する公式手段はない。本フェーズの解決経路は次の非対称構造になる。

- **既知JAN**（`barcode_map` に対応あり）→ オフラインでも即座に詳細へ。
- **未知JAN** → 必ず**タイトル検索（既存S-03）または手動登録（既存F-03後半）を経由**し、登録成功時に `JAN → game_key` を `barcode_map` に学習保存する。
- よって `barcode_map` は **2回目以降のスキャン**で効く。初回はタイトル検索／手動登録が必要、という期待値をUI文言にも織り込む。

## 2. スコープ

### 2.1 含むもの（In Scope）

- FR-1A-01 カメラによる JAN/EAN-13 バーコード読み取り（端末内カメラ、読み取り自体はオフライン完結）
- FR-1A-02 `barcode_map` による解決（ヒット→詳細 / ミス→登録動線）
- FR-1A-03 登録成功時の `JAN → game_key` 学習保存（source 記録）
- FR-1A-04 カメラ非対応・権限拒否時の **手入力JANフォーム**フォールバック
- FR-1A-05 失敗時UX（読取不可・候補多数・トークン未設定・ネットワークなし・BGG未登録の同人）

### 2.2 含まないもの（Out of Scope）

- 箱表紙・棚全体の画像AI認識、Vision LLM（Gemini/OpenAI Vision 等）→ **Phase 1-B**
- `barcode_map` の事前投入（既存YAML/CSVからの一括インポート）→ **別タスク（Phase 1-A+）**。
  - 理由: 現状のanalyzer互換YAMLにJANフィールドが無く取り込める実データが存在しない／file-picker＋パース＋重複マージが加わりスコープが膨らむため。
  - ただし本フェーズの学習保存は将来のimportが**同一のupsert経路を再利用**できる形で実装する（FR-1A-03の設計要件）。
- 対象プラットフォームの拡大（iOS/Desktop/Web）。**Android のみ**を対象とする。

---

## 3. 対象プラットフォーム・非機能要件

| 項目 | 方針 |
|---|---|
| 対象OS | **Android のみ**。iOS/Desktop/Web は対象外（ビルドは壊さないが、カメラ機能は提供しない） |
| カメラ依存 | `mobile_scanner`（stable最新、APIはパッケージ現行版に従う） |
| 権限 | Android: `CAMERA` |
| カメラ非対応時 | Desktop/Web/エミュレータ/権限拒否では **手入力JANフォーム**を表示（機能停止させない） |
| オフライン | 既知JANの解決はオフライン可。未知JANのBGG検索はオンライン前提（オフライン時は手動登録へ誘導） |
| プライバシー | JANコードは個人データではない。新たな機密の取り扱いは発生しない。Phase 0 の鍵非同梱方針を維持 |
| i18n | 追加文言はすべて `assets/i18n/ja.json`・`en.json` のキー経由（ハードコード禁止） |

## 4. 受理バーコード仕様

- **EAN-13**（13桁）を主対象とする。**ISBN-13** は接頭辞 978/979 の EAN-13 と同一文字列としてスキャナが返すため**別扱いしない**。
- **UPC-A**（12桁）は先頭に `0` を付与して EAN-13 へ正規化して扱う（北米流通の同人/輸入対策、任意）。
- 上記以外の形式（QR/Code128 等）は**無視**する。
- チェックディジット検証は行うが、検証失敗時も「読み取れない」として再スキャンに戻す（厳格拒否はしない）。

## 5. 画面要件

### 5.1 S-02 スキャン画面（Phase 0 のプレースホルダを置換）

- カメラプレビュー＋検出枠表示。
- トーチ（フラッシュ）トグル。
- 検出時は**同一JANの連続検出を抑止**（多重発火防止）。
- 解決結果に応じて遷移（§6 フロー）。
- 「JANを手入力」導線を常設（権限拒否・非対応環境では本フォームを主表示にフォールバック）。
- カメラ権限が未許可の場合は許可要求→拒否時は手入力フォーム＋設定アプリへの案内文。

### 5.2 手入力JANフォーム

- 13桁（または12桁UPC-A）の数値入力。
- 確定で §6 と同じ解決経路に入る。

### 5.3 既存画面の再利用

- ヒット時の遷移先: 既存 **S-04 詳細画面**（`GameDetailPage`）。
- ミス時の遷移先: 既存 **S-03 検索登録画面**（`SearchRegistrationPage`）に未解決JANを引き渡し、登録成功時に学習保存する。
- 該当なし時: 既存 **手動登録フォーム**（`LocalGameFormPage`）に未解決JANを引き渡し、ローカル登録成功時に学習保存する。

## 6. 解決フロー

```
[S-02 スキャン] ──検出──> JAN正規化・検証
        │
        ├─ 検証NG ─────────────> 「読み取れません」表示, スキャン継続
        │
        └─ 検証OK ── barcode_map.resolve(jan)
                          │
              ┌── hit ────┴── miss ──┐
              ▼                       ▼
        [S-04 詳細へ]        オンライン？
        (オフライン可)         │
                      ┌── yes ─┴── no ──┐
                      ▼                  ▼
            [S-03 検索(JAN保持)]   「ネットワークなし」
                      │            → 手動登録 or 後で
              ┌── 登録/既存 ──┐
              ▼                ▼
        learn(jan, gameKey)  該当なし
        → [S-04 詳細へ]        │
                              ▼
                      [手動登録(JAN保持)]
                              │
                      learn(jan, localKey)
                      → [S-04 詳細へ]
```

学習保存（`learn`）は `barcode_map` への upsert（PK=janCode、`source` に 'scan'/'manual' を記録）。同一JANが別game_keyへ再学習された場合は最新で上書きする。

## 7. 失敗時UX要件

| 状況 | 挙動 |
|---|---|
| 読み取れない | 検出継続（エラーで止めない）。一定時間未検出時に手入力導線を強調 |
| 候補が多すぎる | 既存S-03の候補一覧で件数表示＋絞り込み（exact一致トグル） |
| BGGトークン未設定 | 既存の設定画面（S-05）誘導ダイアログを再利用 |
| ネットワークなし | 既知JANはオフライン解決。未知JANは手動登録へ誘導（後回し可） |
| BGG未登録の同人 | 手動登録（F-03後半）＋学習保存。以後のスキャンは即ヒット |
| カメラ権限拒否/非搭載 | 手入力JANフォームへフォールバック＋設定アプリ案内 |

---

## 8. 受け入れ基準（概要）

- 既知JANスキャンがオフラインで詳細へ遷移する。
- 未知JANスキャン→タイトル検索→登録成功で `barcode_map` に学習され、**同一JANの再スキャンが即ヒット**する。
- 同人（BGG該当なし）→手動登録でも学習され、再スキャンで即ヒットする。
- 同一JANの連続検出が1回だけ発火する（多重登録が起きない）。
- カメラ権限拒否時に手入力フォームで全動線が成立する。
- `flutter analyze` 警告ゼロ、`flutter test` 全件パス。
- 実機（Android）でE2E（既知→詳細／未知→検索登録→再スキャン即ヒット）が通る。

詳細なタスク分割・定数・実装制約は `docs/DEVELOPMENT_BRIEF_Phase1-A.md` を参照。
