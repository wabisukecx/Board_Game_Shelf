## 1. 目的・背景

登録済みコレクションが増えるほど「何人で遊べる箱が多いか」「重さ・評価の傾向」「メカニクス／カテゴリの偏り」「保管場所」「入手時期」などの**俯瞰**が価値になる。Phase 2 は既存DBの所持データだけを集計して可視化するダッシュボードを追加する。新規のデータ取得は行わない。

### 1.1 設計の前提

- **完全オフライン・読み取り専用。** 外部API・ネットワーク・カメラ・鍵を一切使わない。DBへの書き込みもしない（集計のみ）。
- **既存データのみを集計。** `CollectionRepository.list()` が返す所持データ（Game＋CollectionEntry）を入力にする。新たなフィールド追加・スキーマ変更はしない。
- **欠損を正しく扱う。** ローカル独自レコードやBGG未取得項目は `weight`/`averageRating` などが null。集計では欠損を**除外**し、除外件数を明示する（誤った平均を出さない）。
- **新規依存は原則なし。** 分布・ランキングは組み込みウィジェット（横バー等）で描画する。リッチなチャートが必要になれば `fl_chart` 等を任意で後追加できるが、本フェーズの既定は依存追加なし。
- 集計ロジックは**純Dart**に切り出し、ユニットテストで担保する（UIと分離）。

## 2. スコープ

### 2.1 含むもの（In Scope）

- FR-2-01 概要指標（総所持数、BGG由来/ローカル内訳、平均重さ、平均評価、購入価格合計〔入力済みのみ〕）
- FR-2-02 分布（重さ、プレイ時間、発売年代、評価）
- FR-2-03 人数カバレッジ（各プレイ人数で遊べる所持数）
- FR-2-04 上位ランキング（メカニクス／カテゴリ／デザイナー／パブリッシャーの頻度 Top-N）
- FR-2-05 保管場所別カウント・入手時期の推移
- FR-2-06 分析対象トグル（既定: 所持中のみ／全レコードを含む）と、データ品質ノート（欠損・ローカル件数の明示）

### 2.2 含まないもの（Out of Scope）

- 外部API呼び出し・オンライン集計・クラウド連携
- DBへの書き込み、データ補正、再取得
- エクスポート（分析結果のCSV/画像出力。将来検討）
- リッチチャートライブラリの必須化（任意）
- 既存フェーズの定数・スキーマ・YAML互換・vision/barcode基盤の変更

## 3. 対象・非機能要件

| 項目 | 方針 |
|---|---|
| 対象OS | アプリの対象は引き続き Android。ただし本機能はカメラ/ネットワーク非依存のため全プラットフォームで動作する |
| 依存 | 原則追加なし（組み込みウィジェットで描画）。`fl_chart` 等は任意の将来拡張 |
| 性能 | 1,000件規模でも集計が一瞬で、スクロールがジャンクしない（集計はO(n)、UIは遅延構築） |
| オフライン | 完全オフライン動作 |
| i18n | 追加文言はすべて `assets/i18n/{ja,en}.json` のキー経由（ハードコード禁止） |
| 安全性 | 読み取り専用。既存データを変更しない |

## 4. 集計仕様

入力は所持データ（`CollectionListItem` = Game＋CollectionEntry）。分析対象は既定で `owned = true` のみ（トグルで全件）。

| 指標 | 元データ（型） | 集計方法・注記 |
|---|---|---|
| 総所持数 / 内訳 | `isLocal` | 総数、BGG由来数、ローカル数 |
| 平均重さ | `weight`（double?） | null除外で平均。除外件数を記録 |
| 平均評価 | `averageRating`（String?） | 数値化（パース不能/null除外）で平均 |
| 購入価格合計 | `CollectionEntry.purchasePrice`（double?） | 入力済みのみ合計・平均、入力件数を併記 |
| 重さ分布 | `weight` | バケット境界 C-33 で区分 |
| 時間分布 | `playingTime`（int?） | バケット境界 C-34 で区分 |
| 年代分布 | `yearPublished`（String?） | 数値化して10年刻み等で区分 |
| 評価分布 | `averageRating` | 1刻み（例 6点台/7点台…） |
| 人数カバレッジ | `publisherMinPlayers`/`MaxPlayers`（int?） | 人数 n（C-32範囲）について min≤n≤max を満たす所持数 |
| メカニクス/カテゴリ/デザイナー/パブリッシャー Top-N | 各 `List<String>` | 頻度集計し上位 C-31 件。同数はラベル昇順で安定ソート |
| 保管場所別 | `storageLocation`（String?） | 非空をグループ集計、空は「未設定」 |
| 入手時期推移 | `acquiredDate`（String?） | 年（または年月）単位で件数推移。パース不能/空は除外 |

すべての数値集計は **null/パース不能を除外**し、各指標に「対象N件／除外M件」を持たせる。

## 5. 画面要件

### 5.1 S-09 ダッシュボード画面（新規）

- セクション構成（スクロール）:
  1. **概要**: 指標カード（総所持数・内訳・平均重さ・平均評価・購入価格合計）。
  2. **データ品質ノート**: ローカル件数、weight/rating 欠損件数など「集計から除外した件数」を明示。
  3. **分布**: 重さ・プレイ時間・年代・評価（横バー）。
  4. **人数カバレッジ**: 1〜8人の横バー。
  5. **上位ランキング**: メカニクス／カテゴリ／デザイナー／パブリッシャー Top-N（横バー＋件数）。
  6. **保管/入手**: 保管場所別カウント、入手時期推移。
- **分析対象トグル**: 所持中のみ／全レコードを含む。
- **空状態**: 所持ゼロ件のとき「登録するとここに分析が表示されます」を表示。
- 描画は組み込みウィジェット（横バー＝幅比率、カード＝Card/ListTile）で行う。

### 5.2 導線・既存再利用

- S-01 コレクション一覧の AppBar に「分析」アクション（insights アイコン）を追加し S-09 へ。
- 入力データは既存 `CollectionRepository.list(filter: const CollectionFilter())` を再利用（全件取得し owned はクライアント側で判定）。

## 6. 失敗・端数ケース要件

| 状況 | 挙動 |
|---|---|
| 所持ゼロ件 | 空状態を表示（エラーにしない） |
| 全件 weight/rating 欠損 | 平均は「—（データなし）」表示、除外件数を明示 |
| ローカルのみのコレクション | BGG由来0件として概要に表示、欠損項目は除外件数で説明 |
| 価格未入力が多い | 合計/平均は入力済み件数のみ対象である旨を併記 |
| 日付がパース不能 | 入手時期推移から除外（件数に計上しない） |

---

## 7. 受け入れ基準（概要）

- 所持コレクションから概要・分布・カバレッジ・Top-N・保管/入手が表示される。
- weight/rating/price/date の null・パース不能が集計から除外され、除外件数が明示される。
- 分析対象トグル（所持中のみ／全件）が機能する。
- 所持ゼロ件で空状態、データ全欠損で「—」表示になり、クラッシュしない。
- 集計はDBへ一切書き込まない（読み取り専用）。
- 1,000件規模でスクロールがジャンクしない。
- `flutter analyze` 警告ゼロ、`flutter test` 全件パス（集計ロジックの純Dartユニットテストを含む）。

詳細なタスク分割・定数・実装制約は `docs/DEVELOPMENT_BRIEF_Phase2.md` を参照。
