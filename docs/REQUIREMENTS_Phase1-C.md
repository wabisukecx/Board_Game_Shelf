## 1. 目的・背景

棚に並んだ複数のゲームを**1枚の写真からまとめて候補抽出**し、一括で登録できる経路を追加する。Phase 1-B（1画像=1ゲーム）の自然な発展で、認識→**一括確認**→既存の検索・登録動線への合流という基本構造は踏襲する。最も不確実性が高い領域のため、確認UIで誤りを吸収することを最優先する。

### 1.1 最重要の制約（設計の前提）

- **複数検出は誤り・取りこぼしが前提。** 自動登録は禁止。検出結果は**一括レビューでユーザーが選別・確認**してから、既存の登録動線（S-03/F-03）で確定する。
- **オブジェクト検出・クロップは実装しない。** Gemini マルチモーダルに棚画像を渡し、**検出ゲームのリスト（JSON配列）**を返させる。バウンディングボックス描画やトリミングはしない（1-Bのvisionクライアントを多検出に拡張するだけ）。
- **Vision はタイトル文字列を返すだけ**で、BGG ID を直接確定しない。各候補タイトルを既存BGGタイトル検索（S-03）に投げて確認・登録する。
- **精度の前提**: 背表紙のみの棚は認識精度が大きく落ちる。**箱の表紙が見える向き**を推奨前提とし、取りこぼし・誤検出が起こりうる旨をUIに明示する。
- **外部送信・キー必須**: 棚画像を Gemini（Google）へ送信（ユーザー明示操作のみ）。オンライン必須、既存 secure storage の Gemini キーを再利用。棚画像は情報量が多く**コスト（トークン）が単一箱より高い**点に留意。

## 2. スコープ

### 2.1 含むもの（In Scope）

- FR-1C-01 棚画像の取得（カメラ撮影／ギャラリーアップロード）
- FR-1C-02 Gemini による複数候補の抽出（検出ごとに 推定タイトル〔原語/日本語〕・出版社・確信度。任意で位置ヒント）
- FR-1C-03 検出結果の**一括レビューUI**（チェックボックスで選別、確信度・既登録判定の表示）
- FR-1C-04 選択分を**順次**既存の検索→確認→登録動線へ流す（アイテムごとに 登録済み/スキップ/未処理 を記録）
- FR-1C-05 失敗時UX（キー未設定・ネットワークなし・検出ゼロ・取りこぼし・誤検出・件数過多・コスト）

### 2.2 含まないもの（Out of Scope）

- バウンディングボックス描画・自動クロップ・オンデバイス物体検出
- 背表紙OCRの専用最適化（best-effortで扱うが専用処理は作らない）
- オフライン／オンデバイス画像認識
- Vision結果からのBGG ID直接確定・自動登録
- 対象プラットフォームの拡大（iOS/Desktop/Web）。**Android のみ**

## 3. 対象プラットフォーム・非機能要件

| 項目 | 方針 |
|---|---|
| 対象OS | **Android のみ**（1-A/1-B 踏襲） |
| 画像取得 | 既存 `image_picker` を再利用 |
| Vision | 既存 Gemini マルチモーダル構成を多検出に拡張（モデルIDは定数で切替可） |
| 機密 | 既存 secure storage の Gemini キーを再利用（新規保管しない） |
| ネットワーク | オンライン必須。オフライン時は手動登録へ誘導 |
| プライバシー | 棚画像を Gemini へ送信する旨を明示し、ユーザー明示操作でのみ送信 |
| コスト | 棚画像は高解像度・多トークン。送信前リサイズ（定数）と件数上限で制御。実行前に件数/送信の確認を挟む |
| i18n | 追加文言はすべて `assets/i18n/{ja,en}.json` のキー経由（ハードコード禁止） |

## 4. 認識仕様

- 入力: **棚画像1枚**（撮影またはアップロード）。表紙が見える向きを推奨。
- 前処理: 棚は細部が重要なため、単一箱より**やや大きい長辺上限**でリサイズ＋JPEG圧縮（定数で規定）。
- 推論: Gemini に「棚画像から検出できるボードゲームを**配列**で返す。各要素は title（原語）・japaneseTitle?・publisher?・confidence、任意で positionHint。JSONのみ」と指示。最大検出数で上限。
- 出力: 検出候補リスト（0..上限件）。確信度降順。確信度下限未満は「自信が低い」印をつけて残す（捨てない）。
- 後段: 一括レビュー→選択分を順次、各 title を既存BGGタイトル検索のクエリにして S-03 へ。

## 5. 画面要件

### 5.1 S-08 棚一括認識画面（新規）

- 取得手段の選択（カメラ撮影／ギャラリー）。
- 取得画像のプレビュー。
- **「棚を認識」ボタン（明示送信）。** 送信注記＋「取りこぼし・誤検出が起こりうる」旨を表示。
- 認識中インジケータ。

### 5.2 一括レビュー（S-08 内またはS-09）

- 検出候補リスト（タイトル・出版社・確信度、低信頼の印）。
- 各行のチェックボックスで登録対象を選別（既定: 確信度下限以上をオン）。
- 既にコレクションにありそうな候補（タイトル一致）には「登録済みの可能性」を表示。
- 「選択を順に登録」操作で、各候補を既存の検索登録画面（S-03, initialQuery）へ順次遷移。
- アイテムごとに 未処理／登録済み／スキップ の状態を更新表示。
- 手動検索への切替・個別スキップを常設。

### 5.3 導線・既存再利用

- S-01 のFAB登録メニューに「棚を撮影して一括登録」を追加し S-08 へ。
- 各候補の確定は既存 **S-03**（`SearchRegistrationPage`, `initialQuery`）に合流（1-Bで追加済みの仕組みを再利用）。
- 設定は既存 **S-05**（Geminiキー）。

## 6. 認識・一括登録フロー

```
[S-08 棚一括認識]
   │ 撮影/ギャラリー → プレビュー → 「棚を認識」(明示送信)
   ▼
 キー設定済み？ ──no──> [S-05へ誘導]
   │yes
 オンライン？ ──no──> 「ネットワークなし」→手動登録
   │yes
 Gemini 多検出推論
   │
   ├─ 検出ゼロ ──> 「検出できませんでした」→手動登録/再撮影
   ▼
 [一括レビュー] 候補リスト(確信度/低信頼印/登録済み可能性)
   │ チェック選別 → 「選択を順に登録」
   ▼ (各候補について順次)
 [S-03 検索(initialQuery=候補タイトル)] → 候補確認 → 登録 → 状態=登録済み
   │（スキップ可 / 手動検索切替可）
   ▼
 全件処理後、登録結果サマリを表示 → [S-01 一覧へ]
```

## 7. 失敗時UX要件

| 状況 | 挙動 |
|---|---|
| Gemini APIキー未設定 | 既存 S-05 誘導（1-Bと同じ missingApiKey パターン） |
| ネットワークなし | 「ネットワークなし」を表示し手動登録へ |
| 検出ゼロ | 「検出できませんでした」→再撮影 or 手動登録 |
| 取りこぼし | レビュー画面に「手動で追加」導線を常設（検出されなかった棚も手入力可能） |
| 誤検出 | 各候補をオフ/スキップでき、誤りを登録しないで済む |
| 件数過多 | 最大検出数で上限。超過時は上位（確信度順）に絞る旨を表示 |
| Gemini呼び出し失敗 | エラー画面にせず手動登録へフォールバック |

## 8. 受け入れ基準（概要）

- 棚画像の撮影／アップロード→明示操作でのみGeminiへ送信される。
- 複数候補が確信度順の一括レビューで表示され、選別できる。
- 「選択を順に登録」で各候補が既存S-03に順次流れ、登録済み/スキップ/未処理が更新される。
- 検出ゼロ・低信頼・キー未設定・ネットワークなし・呼び出し失敗で手動登録へフォールバックする。
- 取りこぼしに対して手動追加導線が用意されている。
- 送信注記と「取りこぼし・誤検出が起こりうる」旨が表示される。
- `flutter analyze` 警告ゼロ、`flutter test` 全件パス。
- 実機（Android）でE2E（棚撮影→一括レビュー→複数登録）が通る。

詳細なタスク分割・定数・実装制約は `docs/DEVELOPMENT_BRIEF_Phase1-C.md` を参照。
