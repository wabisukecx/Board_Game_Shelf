## 1. 目的・背景

本アプリの土台は boardgame_analyzer の「analyzer互換YAML」であり、各ゲームの mechanics/categories/ranks/weight/playingTime/minAge/players/year を既にDBに保持している。boardgame_analyzer はこれらから**学習曲線・戦略的深度などの多次元指標**を決定的に算出している。Phase 4 はこの算出ロジックを**純Dartに忠実移植**し、詳細画面と分析ダッシュボードに反映する。新規のデータ取得・外部APIは行わない。

### 1.1 設計の前提

- **完全オフライン・決定的**。外部API・ネットワーク・鍵を使わない。同じ入力からは常に同じ指標が出る（経年係数の「現在年」のみ Clock 注入で制御。下記参照）。
- **計算式は移植元を忠実に再現**（係数の独自チューニング禁止）。移植元: `boardgame_analyzer/src/analysis/{strategic_depth,learning_curve,mechanic_complexity,category_complexity,rank_complexity}.py`。本要件の式は概要であり、**正本は移植元ソース**。
- **重み付けデータは3つのYAMLをアセット同梱**（`mechanics_data.yaml`／`categories_data.yaml`／`rank_complexity.yaml`）。各エントリは `complexity`／`strategic_value`／`interaction_value` を持つ。アプリ内では**読み取り専用**。未知の名称は既定値にフォールバック（YAMLへ書き戻さない）。
- **算出はUIから分離した純Dart**にし、ユニットテストで担保する。
- 新規依存は原則なし（YAMLパースは既存 `yaml`、描画は組み込みウィジェット）。

## 2. スコープ

### 2.1 含むもの（In Scope）

- FR-4-01 重み付けデータ（3 YAML）のアセット同梱と読み取り専用ローダ
- FR-4-02 多次元指標の算出（初期障壁・戦略的深度・リプレイ性・意思決定点・相互作用複雑度・ルール複雑度・メカニクス複雑度・ソロ適性・人数スケーラビリティ・運依存度。各 1.0–5.0）
- FR-4-03 分類（学習曲線タイプ／プレイヤータイプ／習熟時間／戦略的深度・リプレイ性の説明ラベル）
- FR-4-04 詳細画面（S-04）への指標表示
- FR-4-05 分析ダッシュボード（Phase 2）への集計反映（戦略的深度の平均・分布、プレイヤータイプ件数 等）

### 2.2 含まないもの（Out of Scope）

- 類似ゲーム/おすすめ（Voyage AI embeddings。外部・有料）
- ゲーム比較のレーダー専用画面（別フェーズ。指標はここで用意する）
- 移植元の係数の独自チューニング・式の変更
- 重み付けYAMLへの書き戻し・自動追記
- 外部API・オンライン処理
- 対象プラットフォームの拡大（Android のみ）

## 4. 算出仕様（概要）

各ゲーム（Game）から次を算出する。すべて 1.0–5.0 にクランプ。**計算式は移植元に準拠（本表は概要、正本は移植元ソースと開発文書 §6）**。

| 指標 | 主な入力 |
|---|---|
| メカニクス複雑度（平均） | mechanics の complexity 平均 |
| ルール複雑度 | (メカニクス複雑度 × 件数係数) に 0.6 ＋ 年齢 0.2 ＋ weight 0.2 |
| 意思決定点 | mechanics の strategic_value の降順加重平均（要素数別の重みテーブル）＋多様性ボーナス＋playtime補正 |
| 相互作用複雑度 | categories/mechanics の interaction_value 加重（60:40）＋playtime/人数補正 |
| 戦略的深度 | weight0.20＋意思決定0.35＋ルール0.10＋相互作用0.25＋weight0.10＋戦略/隠匿情報/playtimeの各上限付きボーナス、最後に playtime由来の complexity_factor を乗算 |
| 初期障壁 | メカ複雑度0.40＋ルール複雑度0.25＋weight0.20＋(カテゴリ0.6+ランク0.4)0.15、×メカ件数係数 |
| リプレイ性 | 基礎2.0＋多様性/高リプレイメカ/カテゴリ＋ランク連続スコア＋playtime補正、×経年係数 |
| ソロ適性 | Solo/Cooperative/Campaign メカ・最小人数から |
| 人数スケーラビリティ | (最大−最小人数) から |
| 運依存度 | 運メカ−戦略メカ |
| 分類 | 学習曲線タイプ(9)・プレイヤータイプ(複数)・習熟時間(4)・深度/リプレイ性の説明 |

未知のメカニクス/カテゴリ/ランク種別は既定値（メカ complexity 2.5・strategic 3.0・interaction 3.0／カテゴリ complexity 2.5／ランク種別 complexity 3.0）。`weight` 既定3.0、`min_age` 既定10、人数既定 min2/max4、リプレイ性の `playing_time` 既定60 は移植元準拠。`weight`/`year` 等が欠損・パース不能でも例外を出さず既定で算出する。

> 注: 初期障壁内の `complexity_factor`（カテゴリ0.6＋ランク0.4、値域1〜5）と、playtime評価が返す `complexity_factor`（0.85〜1.1の倍率）は**別物**。混同禁止。

## 5. 画面要件

### 5.1 S-04 詳細画面（拡張）

- 「分析」セクションを追加し、10指標を 1.0–5.0 の横バーで表示（組み込みウィジェット）。
- 戦略的深度・リプレイ性は説明ラベル（例: 「非常に深い」）、学習曲線タイプ・プレイヤータイプ・習熟時間も表示。
- ローカル独自レコード等で入力が乏しい場合も既定値で算出し、参考値である旨を添える。

### 5.2 ダッシュボード（Phase 2 拡張）

- 所持コレクションに対する 戦略的深度の平均・分布、プレイヤータイプ件数、習熟時間分布 等を追加（既存の集計に同居）。

### 5.3 既存再利用

- 入力は既存 `Game`（mechanics/categories/ranks/weight/playingTime/publisherMinAge/publisherMin/MaxPlayers/yearPublished）。
- 表示は既存の横バー/カードの描画方針（Phase 2）を踏襲。

## 6. 受け入れ基準（概要）

- 3 YAML がアセット同梱され、読み取り専用で参照される（書き戻しなし）。
- 既知ゲームの各指標が移植元と同等（許容誤差内）に算出される。
- 未知名称・欠損入力でも例外なく既定値で算出され、全指標が 1.0–5.0 に収まる。
- 詳細画面に10指標＋分類が表示される。
- ダッシュボードに戦略的深度の平均・分布等が表示される。
- 算出がDB・アセットを書き換えない（読み取り専用）。
- `flutter analyze` 警告ゼロ、`flutter test` 全件パス（移植ロジックの純Dartユニットテストを含む）。

詳細なタスク分割・定数・移植式・実装制約は `docs/DEVELOPMENT_BRIEF_Phase4.md` を参照。
