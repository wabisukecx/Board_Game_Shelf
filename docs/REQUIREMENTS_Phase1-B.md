## 1. 目的・背景

バーコードが無い・読めない箱（同人、海外旧版、シュリンク無し等）に対し、**箱表紙を1枚撮影／アップロードして候補ゲームを推定**する経路を追加する。Phase 1-A と同じく「認識→候補確認→既存の検索・登録動線に合流」の形を取り、認識の不確実性を後段のユーザー確認で吸収する。

### 1.1 最重要の制約（設計の前提）

- **Vision出力は確率的で誤りうる。** 認識結果を自動登録してはならない。必ず**候補提示→ユーザー確認**を挟み、確定は既存の登録動線（S-03/F-03）で行う。
- **VisionはBGG IDを直接返さない。** Geminiが返すのは推定タイトル/出版社などの文字列。これを**既存のBGGタイトル検索（S-03）のクエリに変換**して候補を得る。Vision結果をBGG IDとして直接登録する実装は作らない。
- **外部送信が発生する。** 画像は Gemini（Google）へ送信される。**ユーザーの明示操作を起点**とし（自動送信しない）、送信が発生する旨をUIに明示する。オンライン必須・Gemini APIキー必須。
- **キー基盤は既存を再利用。** Gemini APIキーは Phase 0 の secure storage（翻訳機能と共用）に保存済みのものを使う。新たな鍵保管・同梱は行わない（鍵非同梱方針を維持）。

## 2. スコープ

### 2.1 含むもの（In Scope）

- FR-1B-01 箱表紙画像の取得（端末カメラ撮影／ギャラリーからのアップロード）
- FR-1B-02 Gemini マルチモーダルによる候補抽出（推定タイトル〔原語/日本語〕・出版社・確信度を構造化出力）
- FR-1B-03 候補タイトルを既存BGGタイトル検索（S-03）のクエリへ変換し、候補確認→既存登録動線へ合流
- FR-1B-04 確信度が低い／抽出不能な場合の手動検索フォールバック
- FR-1B-05 失敗時UX（キー未設定・ネットワークなし・抽出不能・候補多数・誤認）

### 2.2 含まないもの（Out of Scope）

- **棚全体の複数ゲーム同時検出・自動クロップ・バウンディングボックス** → **Phase 1-C**
- バーコード読み取り（Phase 1-A 済）
- オフライン／オンデバイス画像認識（TFLite 等）。本フェーズはオンラインのGemini前提
- Vision結果からのbarcode_map学習（JANが無いため対象外。barcode_mapは1-Aのスキャン経路専用のまま）
- 対象プラットフォームの拡大（iOS/Desktop/Web）。**Android のみ**

## 3. 対象プラットフォーム・非機能要件

| 項目 | 方針 |
|---|---|
| 対象OS | **Android のみ**（Phase 1-A 踏襲）。iOS/Desktop/Web は対象外（ビルドは壊さない） |
| 画像取得 | `image_picker`（カメラ撮影／ギャラリー選択） |
| Vision | Gemini マルチモーダル（current stable、モデルIDは設定/定数で切替可能）。既存の翻訳クライアント構成を踏襲 |
| 機密 | Gemini APIキーは既存 secure storage を再利用（翻訳と共用）。新規保管しない |
| ネットワーク | オンライン必須。オフライン時は手動検索へ誘導 |
| プライバシー | 画像をGemini（Google）へ送信する旨を明示し、ユーザーの明示操作でのみ送信。送信は箱表紙画像のみ（位置情報・個人データを含めない） |
| i18n | 追加文言はすべて `assets/i18n/{ja,en}.json` のキー経由（ハードコード禁止） |

## 4. 認識仕様

- 入力: **箱表紙1枚**の画像（撮影またはアップロード）。
- 前処理: 送信量制御のため長辺を上限値にリサイズ＋JPEG圧縮（定数で規定）。
- 推論: Gemini マルチモーダルに「ボードゲームの箱表紙画像から、推定タイトル（原語・日本語）・出版社・確信度を構造化（JSON）で返す」プロンプトを与える。出力は**JSONのみ**（前置き・マークダウン無し）を要求し、安全にパースする。
- 出力: 候補（最大N件）。各候補は `title` / `japaneseTitle?` / `publisher?` / `confidence`。
- 後段: 最有力候補（または選択候補）の `title` を既存BGGタイトル検索のクエリにして S-03 の候補一覧へ。確信度が下限未満なら「自信がありません」を表示し手動検索へ誘導。

## 5. 画面要件

### 5.1 S-07 画像認識画面（新規）

- 取得手段の選択（カメラ撮影／ギャラリーから選択）。
- 取得画像のプレビュー表示。
- **「この箱を認識」ボタン（明示送信）。** 押下時に「画像をGeminiに送信します」の注記を表示。
- 認識中インジケータ。
- 結果表示: 候補タイトルのリスト（確信度つき）。タップで既存の検索登録画面（S-03）へクエリを引き渡し。
- 低信頼/抽出不能/失敗時: 手動検索（S-03）への導線。

### 5.2 導線

- S-01 コレクション一覧の登録メニュー（FAB）に「写真で認識」を追加し、S-07 へ。
- （任意）S-02 スキャン画面からも「写真で認識」へ切替できると望ましい。

### 5.3 既存画面の再利用

- 候補確定の遷移先: 既存 **S-03 検索登録画面**（`SearchRegistrationPage`）に推定タイトルを **initialQuery** として引き渡し、自動検索→候補確認→登録。
- 設定: 既存 **S-05**（Gemini APIキー保存）をそのまま使用。

```
                                              │
                              ┌── no ─────────┴── yes ──┐
                              ▼                          ▼
                       [S-05 設定へ誘導]          オンライン？
                                              ┌── no ─┴── yes ──┐
                                              ▼                  ▼
                                       「ネットワークなし」  Gemini Vision 推論
                                       → 手動検索             │

                                                    ▼                                  ▼
                                          候補タイトル一覧                    「自信がありません」
                                                    │ タップ                  → 手動検索(S-03)
                                                    ▼
                                  [S-03 検索(initialQuery=推定タイトル)]
                                                    │
                                            候補確認 → 登録（既存動線）
                                                    ▼
                                              [S-04 詳細へ]
```

## 7. 失敗時UX要件

| 状況 | 挙動 |
|---|---|
| Gemini APIキー未設定 | 既存の設定画面（S-05）誘導（翻訳機能と同じ missingApiKey パターンを再利用） |
| ネットワークなし | 「ネットワークなし」を表示し手動検索（S-03）へ誘導 |
| 抽出不能／確信度が低い | 候補を出さず「自信がありません」を表示し手動検索へ |
| 候補が多すぎる | 既存S-03の候補一覧で件数表示＋絞り込み |
| 誤認（候補が誤り） | ユーザーが候補を選ばず手動検索に切替できる導線を常設 |
| Gemini呼び出し失敗 | エラー画面にせず、手動検索へフォールバック |

## 8. 受け入れ基準（概要）

- 箱表紙画像の撮影／アップロードができ、明示操作でのみGeminiへ送信される。
- 抽出された推定タイトルが既存S-03に引き渡され、候補確認→登録までつながる。
- 確信度下限未満で「自信がありません」→手動検索に落ちる。
- Gemini APIキー未設定時に設定画面へ誘導され、クラッシュしない。
- ネットワークなし／呼び出し失敗で手動検索にフォールバックする。
- 画像送信の注記がUIに表示される。
- `flutter analyze` 警告ゼロ、`flutter test` 全件パス。
- 実機（Android）でE2E（撮影→認識→候補→検索登録→詳細）が通る。

詳細なタスク分割・定数・実装制約は `docs/DEVELOPMENT_BRIEF_Phase1-B.md` を参照。
