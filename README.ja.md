# Board Game Shelf

[English](README.md) | [日本語](README.ja.md)

Board Game Shelf は、ボードゲームコレクションを管理する Flutter 製アプリです。BoardGameGeek（BGG）データの登録、ローカル専用ゲームの追加、写真からの箱・棚認識、ローカルでの分析ダッシュボード、analyzer 互換 YAML のエクスポートに対応します。

本アプリは **API キーがなくても使える** ように設計されており、自分の BGG トークンや Gemini API キーを登録すると、オンライン機能が追加で有効になります。各構成で何が使えるかは [API キーなしでの機能可用性](#api-キーなしでの機能可用性) を参照してください。

## セットアップ

1. Flutter をインストールし、`flutter pub get` を実行します。
2. `flutter test` でテストを実行します。
3. `flutter run` でアプリを起動します。

## API キーと機能可用性

本アプリは API キーをリポジトリやビルド済みバイナリに同梱しません。登録したキーは端末のセキュアストレージにのみ保存され、SQLite データベースへの書き込み・エクスポート・出力は一切行いません。

### API キーなしでの機能可用性

| 機能 | キーなし | BGG トークンのみ | Gemini キーのみ | 両方 |
| --- | --- | --- | --- | --- |
| ローカル専用ゲーム登録（手動追加） | ✅ | ✅ | ✅ | ✅ |
| ローカルコレクションの閲覧・検索・フィルター | ✅ | ✅ | ✅ | ✅ |
| 分析ダッシュボード・学習分析 | ✅ | ✅ | ✅ | ✅ |
| YAML エクスポート、バックアップ／復元 | ✅ | ✅ | ✅ | ✅ |
| バーコードスキャン → 既知 JAN（オフライン地図ヒット） | ✅ | ✅ | ✅ | ✅ |
| バーコードスキャン → 未知 JAN（GameUPC 公開テスト API） | ✅¹ | ✅¹ | ✅¹ | ✅¹ |
| BGG タイトル検索・登録 | ❌ | ✅ | ❌ | ✅ |
| BGG コレクション一括インポート | ❌ | ✅ | ❌ | ✅ |
| 拡張候補の発見（BGG リンクから） | ❌ | ✅ | ❌ | ✅ |
| 説明文の日本語翻訳 | ❌ | ❌ | ✅ | ✅ |
| 写真からの箱カバー認識 | ❌ | ❌² | ✅ | ✅ |
| 棚の一括認識 | ❌ | ❌² | ✅ | ✅ |

¹ GameUPC のルックアップは現在キー不要の公開テストエンドポイントを使いますが、マッチしたゲームを実際に**登録**するには BGG トークンが必要です。BGG トークンがない場合、未知 JAN はルックアップできても BGG フロー経由でコレクションに登録できません。

² 写真認識・棚認識は**タイトル候補**を出すだけです。候補をタップすると BGG 検索・登録フローに引き継がれ、実際の登録には BGG トークンが必要です。

#### BGG トークンがない場合

BGG 検索・登録・コレクションインポート・拡張発見は利用できません。それでも **手動（ローカル専用）登録** だけでコレクションを構築でき、フィルター・分析・学習分析・エクスポート・バックアップといったオフライン機能はすべてフルに動作します。

#### Gemini API キーがない場合

説明文の日本語翻訳、写真からの箱カバー認識、棚の一括認識は利用できません。アプリは手動検索・手動追加にフォールバックします。翻訳前（オリジナル）の説明文はそのまま利用できます。

### キーの取得方法

**BoardGameGeek トークン。** BGG 検索・登録には Bearer トークンを使います。BoardGameGeek の API ページ（<https://boardgamegeek.com/applications>）から API トークンを申請してください。承認には 1 週間以上かかることがあります。承認後、発行されたトークンをアプリの設定画面で保存します。

**Gemini API キー。** 設定画面で自分の Gemini API キーを保存すると、翻訳と写真／棚認識が有効になります。同じキーが翻訳と Vision 機能の両方で再利用されます。日本語文字の比率がすでに 20% を超える説明文は翻訳をスキップします。翻訳失敗は無視され、オリジナルの説明文が残ります。

## コレクション一覧

- ゲームはリスト表示（デフォルト）またはグリッド表示で表示されます。
- **拡張は親となる基本ゲームの下にネストされ、デフォルトで折りたたまれています。** 拡張を持つ基本ゲームには拡張数とシェブロンが表示され、行をタップすると拡張の展開／折りたたみが切り替わります。展開状態はビュー内でのみ保持され、永続化されません。拡張を持たない基本ゲームにはシェブロンやバッジは表示されません。
- グリッド表示は既存のレイアウトを維持し、拡張にはバッジを付けます。

## フィルター

コレクション画面からフィルターを開きます。各フィルターは AND 条件で組み合わされます。

- タイトル検索
- プレイ人数
- 最大プレイ時間
- ローカル専用
- メカニクス／デザイナー
- 拡張ありのみ
- 未プレイのみ
- **プレイ対象（初心者／経験者）。** BGG の Weight（複雑さ）から自動判定されます。
  - 初心者（Beginner）: Weight が 2.0 未満
  - 経験者（Advanced）: Weight が 2.0 以上
  - Weight 値を持たないゲームは Unknown として扱われ、どちらの対象フィルターにもマッチしません。

  しきい値は単一の定数として定義されており調整可能です。将来用に、より細かい 3 段階分割（経験者の上位カットオフを 3.0 とする）も定数として予約されています。

## ローカル専用ゲーム

「ローカル専用」とは、**ローカルデータベースにのみ存在し BGG オブジェクトに紐付かない**ゲームを指します。典型的には自費出版・同人ゲーム、または手動登録で自分で追加したタイトルです。ローカル専用ゲームは第一級のコレクションレコードであり、BGG 登録ゲームとまったく同じようにフィルター・分析・エクスポート・バックアップできます。BGG ID を持たないため、BGG から取得されることも BGG へ書き戻されることもありません。

## 分析ダッシュボード

ローカルコレクションの読み取り専用分析ダッシュボードです。

- コレクションの AppBar から Analytics を開きます。
- ダッシュボードはローカルデータベースのレコードのみを使用します。外部 API の呼び出し、カメラの使用、分析結果のデータベースへの書き戻しは行いません。
- デフォルトの対象は所有レコードのみで、トグルで全コレクションレコードを含められます。
- **分析は常に基本ゲームのみを対象とし、拡張はすべての集計から除外されます**（タイトル数、Weight・プレイ時間の平均、評価、メカニクス／カテゴリ／デザイナー／パブリッシャー集計、各種分布、学習分析）。これは、基本ゲームとメカニクスやメタデータを共有し独自の BGG 値を持たないことの多い拡張レコードがデータを歪めるのを防ぐためです。すべての分析が単一の共通の基本ゲームフィルターを経由するため、このルールは一貫して適用されます。
- 欠損値・パース不能な値は平均から除外され、除外件数として表示されます。
- 組み込みの横棒グラフで、Weight、時間、プレイ人数カバレッジ、年代、評価、上位メカニクス／カテゴリ／デザイナー／パブリッシャー、保管場所、月別取得数を、チャート依存なしで表示します。

### 学習分析

同梱の `boardgame_analyzer` YAML テーブルに基づくローカルの多次元学習分析です。

- ゲーム詳細では、初期障壁、戦略的深さ、リプレイ性、意思決定ポイント、相互作用の複雑さ、ルールの複雑さ、メカニクスの複雑さ、ソロ適性、プレイ人数スケーラビリティ、運依存度を表示します。
- Analytics では、平均初期障壁、戦略的深さ、リプレイ性、学習曲線タイプ、プレイヤータイプ、習熟時間、戦略的深さの分布を要約します。
- 分析はローカル専用です。外部 API の呼び出し、シークレットの保存、YAML のディスクへの書き戻し、analyzer テーブルアセットの変更は行いません。
- 未知のメカニクス／カテゴリ／ランクタイプは、保留 YAML エントリを作らず、文書化されたフォールバック値を使用します。

## バーコードスキャン

Android での JAN/EAN-13 バーコード登録に対応します。

- カメラは EAN-13 と UPC-A を読み取ります。UPC-A は先頭に `0` を付けて EAN-13 に正規化します。
- JAN がローカルのバーコードマップに既にある場合、アプリはオフラインでゲーム詳細を開きます。
- 未知の JAN は、手動 BGG 検索にフォールバックする前に GameUPC でルックアップします。現在の公開テスト API は API キーなしで動作します。
- GameUPC が検証済みの BGG ゲームを返した場合、アプリは BGG 登録フロー（BGG トークンが必要）で登録し、JAN とゲームの対応を保存します。
- GameUPC が複数候補を返した場合、アプリは 1 つを選ぶよう求め、GameUPC への投票には日本語版があればそれを（なければ英語版を）優先し、安定した端末ユーザー ID で選択を GameUPC に投稿してから、登録と JAN の紐付けを行います。
- GameUPC が未設定、またはマッチが見つからない場合、未知の JAN は BGG 検索または手動登録に進みます。成功時には次回用に対応が保存されます。
- iOS・デスクトップ・Web・権限拒否・カメラ利用不可の環境では、手動 JAN 入力フォームにフォールバックします。
- Android では `CAMERA` 権限が必要です。

アプリは JAN 値をバーコードルックアップとして BGG に直接送信しません。BGG 検索はタイトルベースのままで、GameUPC は任意の UPC→BGG ブリッジです。

## 写真認識

Android での単一の箱カバー認識（Gemini API キーが必要）。

- 箱カバー写真を撮影するかギャラリーから選び、明示的に認識ボタンを押します。画像はその操作の後にのみ Gemini に送信されます。
- 認識はタイトル候補のみを返します。BGG ID を決定したり、ゲームを自動登録したりすることはありません。
- 候補をタップすると BGG タイトル検索フローが開き、そこで確認・登録します。
- キーがない、ネットワークが利用できない、または確信度が低い場合、アプリは手動検索にフォールバックします。

## 棚の一括認識

1 枚の棚写真からの候補一括抽出（Gemini API キーが必要）。

- 棚写真を撮影するかギャラリーから選び、明示的に認識ボタンを押します。画像全体はその操作の後にのみ Gemini に送信されます。アプリはクロップ、ローカルでの物体検出、端末側 ML を行いません。
- 認識は候補タイトルのレビューリストを返します。低確信度の候補は表示されますがデフォルトでオフです。
- 既存コレクションのタイトル一致は所有済みの可能性ありとして印が付き、重複を避けられます。
- 選択した候補は 1 件ずつ BGG 検索・登録フローに送られます。アプリはゲームを自動登録せず、Vision の出力を確定 BGG ID として扱うこともありません。
- 棚写真はゲームを取りこぼしたり誤検出を含んだりすることがあり、単一の箱写真よりトークンを多く消費します。取りこぼしは手動検索や手動追加を使ってください。

## BGG コレクションインポート

所有する BoardGameGeek コレクションの手動一括インポート（BGG トークンが必要）。

- 設定で BGG ユーザー名を保存し、BGG Bearer トークンを設定したままにします。アイテム詳細は BGG 登録フローで登録されます。
- Add を開き、Import from BGG collection を選びます。
- まずコレクションを取得します。アプリは `own=1` と `subtype=boardgame` で所有ボードゲームのみを要求します。
- 総数／新規／登録済みの件数を確認してから、明示的にインポートを開始します。
- 新規の BGG オブジェクト ID のみが既存の登録パスに送られます。登録済みゲームはスキップされるため、インポートの再実行は冪等です。
- 進捗、キャンセル、部分的な結果、連続失敗による停止がインポート画面に表示されます。
- 評価、コメント、プレイ回数、BGG への書き戻し、自動同期は対象外です。

## 拡張管理

- BGG の `boardgameexpansion` リンクは登録フロー中に解析されます。
- 基本ゲームは、登録直後に未登録の拡張候補を表示できます。
- 拡張は `gameKind=expansion` と任意の `parentGameKey` を持つ通常のコレクションレコードとして保存されます。
- 親ゲームを先に登録する必要はありません。拡張詳細画面から後で親を登録できます。
- リスト表示では拡張が親ゲームの下にネストされ（デフォルトで折りたたみ）、グリッド表示では拡張バッジが付きます。
- 学習分析は基本ゲームのみのままで、拡張詳細ページは学習メトリクスの代わりに通知を表示します。
- analyzer 互換 YAML エクスポートは変更されておらず、拡張固有のキーは追加しません。

## バックアップ

データベースバックアップは固定の互換名を使用します。

- 自動バックアップ: `YYMMDD.sqlite`
- 手動バックアップ: `backup_YYYYMMDD_HHMMSS.sqlite`
