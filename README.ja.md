# Board Game Shelf

[English](README.md) | [日本語](README.ja.md)

Board Game Shelf は、ボードゲームの所持コレクションを管理する Flutter アプリです。BoardGameGeek (BGG) のデータ登録、ローカル独自レコード、バーコードスキャン、箱写真や棚写真からの候補認識、ローカル分析ダッシュボード、互換 YAML エクスポートに対応しています。

API キーがなくても基本機能を使えるように設計されています。BGG トークンや Gemini API キーを登録すると、オンライン機能が追加で有効になります。

## セットアップ

1. Flutter をインストールし、`flutter pub get` を実行します。
2. `flutter test` でテストを実行します。
3. `flutter run` でアプリを起動します。

## 対応プラットフォーム

このアプリは **Android のみ** を対象にしています。

- **Android**: 対応。バーコード、箱写真、棚写真のカメラ機能を含めて利用できます。
- **iOS**: 対象外です。`ios/` ディレクトリは Flutter ツール互換のため残していますが、ビルド・テスト・保守対象ではありません。
- **Desktop / Web**: 対象外です。カメラやスキャン機能は手入力へフォールバックします。

## 多言語化

UI 文言は `assets/i18n/` 配下の JSON バンドル (`ja.json`, `en.json` など) から読み込まれます。

- デフォルトは「システムに従う」です。端末言語に一致するバンドルがあれば、それを使用します。
- 一致する言語がない場合は英語にフォールバックします。英語バンドルもない場合は、利用可能な最初のバンドルを使用します。
- 設定画面から言語を手動選択できます。選択は即時に UI へ反映され、アプリ再起動後も保持されます。
- ゲーム名表示も UI 言語に連動します。日本語 UI では日本語名、英語 UI では英語名を優先し、日本語名がないゲームは BGG の primary/英語名にフォールバックします。
- 検索は表示言語に関係なく、保存されている全言語名を対象にします。日本語名、英語名、別名のいずれでも検索できます。
- 言語設定は `shared_preferences` に保存します。API キーやトークンは従来どおりセキュアストレージに分離されています。

### 他の言語を追加するには

1. 既存の JSON を `assets/i18n/<locale>.json` としてコピーし、値を翻訳します。キー構造は維持してください。
2. トップレベルに `"_meta": {"locale": "fr", "name": "Français"}` のようなメタ情報を追加します。`_meta` がない場合は、ファイル名が言語コード・表示名として使われます。
3. `pubspec.yaml` は `assets/i18n/` フォルダ指定済みなので、新しい JSON ごとの追記は不要です。
4. アプリを再起動すると、設定画面の言語選択肢に自動で表示されます。

## API キーと機能

API キーはリポジトリやビルド済み APK に同梱しません。ユーザーが入力したキーは端末のセキュアストレージにのみ保存され、SQLite データベース、YAML エクスポート、ログ出力には含めません。

| 機能 | キーなし | BGG トークン | Gemini キー | 両方 |
| --- | --- | --- | --- | --- |
| 手動登録、閲覧、検索、絞り込み | 可 | 可 | 可 | 可 |
| 分析、学習分析、YAML エクスポート、バックアップ | 可 | 可 | 可 | 可 |
| 既知 JAN のバーコードスキャン | 可 | 可 | 可 | 可 |
| 未知 JAN の GameUPC 照会 | 可 | 可 | 可 | 可 |
| BGG 検索・登録 | 不可 | 可 | 不可 | 可 |
| BGG コレクション一括取り込み | 不可 | 可 | 不可 | 可 |
| 拡張候補の取得 | 不可 | 可 | 不可 | 可 |
| 箱写真・棚写真の認識 | 不可 | 不可 | 可 | 可 |

GameUPC の公開テスト API は現在 API キーなしで照会できます。ただし、照会結果を BGG ゲームとして登録するには BGG トークンが必要です。

### キーの取得

**BoardGameGeek トークン**: BGG 検索・登録には Bearer トークンを使います。BoardGameGeek の API ページ (<https://boardgamegeek.com/applications>) から申請し、承認後に設定画面で保存してください。承認には 1 週間以上かかる場合があります。

**Gemini API キー**: 設定画面で Gemini API キーを保存すると、箱写真認識と棚写真の一括認識が有効になります。

## コレクション一覧

- ゲームはリスト表示またはグリッド表示で閲覧できます。
- 拡張セットは親となる基本ゲームの下にネストされ、デフォルトでは折りたたまれます。
- 拡張を持つ基本ゲームには「拡張 N 個」のバッジと展開アイコンを表示します。
- 展開状態は画面内だけで保持され、永続化はしません。
- グリッド表示では拡張バッジを付けて表示します。

## フィルター

コレクション画面から以下の条件で絞り込めます。複数条件は AND で結合されます。

- タイトル検索
- プレイ人数
- 最大プレイ時間
- ローカルのみ
- メカニクス / デザイナー
- 拡張ありのみ
- 未プレイのみ
- プレイ対象 (初心者向け / 経験者向け)

プレイ対象は BGG Weight (complexity) から自動判定します。

- 初心者向け: Weight が 2.0 未満
- 経験者向け: Weight が 2.0 以上
- Weight 未取得: 未判定として扱い、どちらのフィルターにも自動では含めません

## ローカル独自レコード

「ローカルのみ」とは、BGG オブジェクトに紐づかずローカルデータベースにだけ存在するゲームです。同人ゲーム、自作ゲーム、手動で登録したタイトルなどを想定しています。ローカル独自レコードも、BGG 登録ゲームと同様に検索、絞り込み、分析、エクスポート、バックアップの対象になります。

## 分析ダッシュボード

ローカルデータベースの内容だけを使う読み取り専用の分析画面です。外部 API 呼び出し、カメラ利用、分析結果のデータベース書き戻しは行いません。

- デフォルトは所持中レコードのみを対象にします。
- トグルで全レコードを含められます。
- 分析対象は常に基本ゲームのみです。拡張セットはタイトル数、Weight 平均、プレイ時間平均、評価、メカニクス、カテゴリ、デザイナー、出版社、分布、学習分析のすべてから除外します。
- 欠損値や不正値は平均から除外し、除外件数として表示します。
- Weight、時間、人数カバレッジ、年代、評価、上位メカニクス、カテゴリ、デザイナー、出版社、保管場所、入手月推移を表示します。

### 学習分析

同梱の `boardgame_analyzer` YAML テーブルに基づき、ローカルで多次元の学習分析を行います。

- ゲーム詳細では、初期ハードル、戦略深度、リプレイ性、意思決定量、インタラクション複雑度、ルール複雑度、メカニクス複雑度、ソロ適性、人数スケーラビリティ、運依存度を表示します。
- 分析画面では、平均値、学習曲線タイプ、プレイヤータイプ、習熟時間、戦略深度分布を集計します。
- 未知のメカニクス、カテゴリ、ランク種別は保守用 YAML を増やさず、定義済みのフォールバック値を使用します。

## プレイ記録

基本ゲームの詳細画面からプレイ記録を追加できます。

- 日付、人数、実プレイ時間、評価、また遊びたい度、体感の重さ、感想メモ、勝者メモを保存できます。
- その基本ゲームに紐づく拡張セットを複数選択して、「この回で使った拡張」として記録できます。
- 拡張セット自体にはプレイ記録を付けず、親の基本ゲームから記録します。
- プレイ傾向画面では、よく遊ぶメカニクス、よく遊ぶデザイナー、評価が高い傾向、拡張使用回数、人数別評価、最近遊んでいない高評価ゲームなどを確認できます。

## バーコードスキャン

Android で JAN / EAN-13 バーコード登録に対応しています。

- カメラは EAN-13 と UPC-A を読み取ります。UPC-A は先頭に `0` を付けて EAN-13 として正規化します。
- JAN がローカルのバーコードマップに登録済みなら、オフラインでゲーム詳細を開きます。
- 未知 JAN は、ローカル学習済みマップ、内蔵 GameUPC オフラインデータ、GameUPC API、手動検索の順で解決します。
- GameUPC オフラインデータはAPIキーなしで利用でき、設定画面から手動で最新版へ更新できます。更新に失敗しても既存データは保持されます。
- GameUPC が verified の BGG ゲームを返した場合、BGG 登録フローで登録し、JAN とゲームの対応を保存します。
- GameUPC が複数候補を返す場合はユーザーに選択を求め、日本語版を優先し、なければ英語版を優先して GameUPC に投票します。
- カメラが使えない環境では、JAN 手入力フォームにフォールバックします。
- Android では `CAMERA` 権限が必要です。

BGG には JAN を直接送信しません。BGG 検索はタイトルベースで行い、GameUPC は UPC/JAN から BGG 候補へつなぐ補助サービスとして使います。

オフラインデータ提供: [GameUPC](https://gameupc.com)

## 写真認識

Android で箱カバー写真から候補タイトルを抽出できます。Gemini API キーが必要です。

- 写真を撮影またはギャラリーから選択し、明示的に認識ボタンを押したときだけ Gemini に送信します。
- 認識結果はタイトル候補のみです。BGG ID を確定したり、自動登録したりはしません。
- 候補をタップすると BGG 検索・登録フローへ進み、ユーザーが確認して登録します。
- キー未設定、ネットワーク不可、低信頼の場合は手動検索へフォールバックします。

## 棚写真の一括認識

Android で棚写真から複数の候補タイトルを抽出できます。Gemini API キーが必要です。

- 棚写真を撮影または選択し、明示的に認識ボタンを押したときだけ Gemini に送信します。
- 認識結果はレビュー用の候補一覧です。低信頼候補は表示されますが、デフォルトでは選択されません。
- 既存コレクションに近いタイトルは重複候補として表示します。
- 選択した候補は 1 件ずつ BGG 検索・登録フローへ送ります。
- 棚写真は取りこぼしや誤検出があり得るため、必要に応じて手動検索や手動追加を使ってください。

## BGG コレクション一括取り込み

BGG の所持コレクションを手動で一括取り込みできます。BGG トークンが必要です。

- 設定画面で BGG ユーザー名と BGG Bearer トークンを保存します。
- 登録メニューから「BGG コレクションから一括取り込み」を開きます。
- まずコレクションを取得し、合計件数、新規件数、既登録件数を確認します。
- 新規 BGG ID のみを既存の登録フローへ送ります。
- 既登録ゲームはスキップされるため、再実行しても重複登録されません。
- 進捗、キャンセル、部分結果、連続失敗による停止を画面に表示します。

## 拡張セット管理

- BGG の `boardgameexpansion` リンクを登録フローで解析します。
- ゲーム登録時に拡張候補は自動表示されません。関連ゲームを追加したい場合は、ゲーム詳細画面の「拡張候補を確認」から未登録候補を表示できます。
- 拡張セットは通常のコレクションレコードとして保存し、`gameKind=expansion` と任意の `parentGameKey` を持ちます。
- 親ゲームが未登録でも拡張セットを登録できます。拡張詳細画面から親ゲームを後で登録できます。
- BGG から複数の親ゲーム候補が返る場合は、登録時または拡張詳細画面から正しい版を手動で選択できます。
- リスト表示では登録済み拡張を親ゲームの下にネストし、デフォルトで折りたたみます。
- 学習分析は基本ゲームのみを対象にし、拡張詳細画面では案内文を表示します。
- analyzer 互換 YAML エクスポートに拡張専用キーは追加しません。

## バックアップ

データベースバックアップは互換性のある固定名を使います。

- 自動バックアップ: `YYMMDD.sqlite`
- 手動バックアップ: `backup_YYYYMMDD_HHMMSS.sqlite`
